# 개념 지도와 렌더링 비용 개선

## 확인한 원인과 변경

기존 관계도는 모든 용어·관계를 Cytoscape에 올린 뒤 CoSE 배치와 별도 프레임 기반 물리 계산을 수행했다. 클릭 시 계산을 재개하고, 숨겨진 화면에서도 컴포넌트가 유지되었다. 노드 밀도와 반복 충돌·반발 계산이 탐색 부담과 렌더링 비용을 함께 키우는 구조였다.

- 전체 지도는 주제 묶음과 페이지 단위 용어 목록으로 대체했다. 기존 용어 데이터는 삭제하지 않았다.
- 중심 개념은 직접 연결 12개부터 표시하며 12개씩 더 펼친다. 같은 이웃의 복수 관계는 합쳐서 노드 중복을 피한다.
- 최초 한 번 인접 인덱스를 만들고, 중심이 바뀔 때 해당 이웃만 조회한다. 고정 HTML/SVG 배치로 물리 계산과 캔버스 렌더링을 제거했다.
- 단방향 causal/policy 관계만 원인/결과 쪽에 놓는다. 성격 미분류·상관·정의·분류·양방향은 별도로 표시하고 원문 방향 및 역방향 설명을 보존한다.
- 노드를 선택하면 상세 패널에서 관계·조건·시차를 확인한다. 중심 전환, 이전 개념, 최근 6개 탐색 경로를 제공한다. 탐색 경로를 인과 사슬이라고 표시하지 않는다.
- 학습 파트를 선택하거나 학습 화면에서 진입하면 해당 파트의 용어를 우선한다. 명시적인 관계가 없는 동시 등장은 연결선으로 만들지 않는다.
- 모바일에서는 축소된 그래프 대신 방향별 연결 목록을 제공하고 선택한 설명으로 이동한다.
- 기존 Home의 중복 검색·가이드 화면은 지도 내부의 검색·주제 탐색으로 통합했다. 명제·배움 표시·이력은 개념 상세에서 접근한다.

## 검증

- `npm run build`, 최종 `npx tsc --noEmit` 및 `npx vite build`.
- `node scripts/check-graph-explorer.js`: 492개 중심 / 1,310개 관계의 연결 정합, 12개 초기 제한, 확장 좌표 유지, 방향 분류, 누락 참조 방어, 첫 화면 서버 렌더링 검사.
- 같은 검사에서 전체 중심의 조회와 assertions가 약 19~28ms 소요되었다. Node 환경의 조회 검사이며 실제 브라우저 FPS 측정은 아니다.
- `node scripts/check-learning-ui.js`, `node scripts/check-learning-render.js`: 기존 학습 UI와 118개 본문 검사.
- 실제 브라우저: 주제 진입, 금리→주식시장→이전 개념, 12→24개 확장, 탐색 경로, SOFR 검색과 빈 결과, 학습 파트 자동 전달 및 복귀를 확인했다.
- 데스크톱 1440×1000/1280×900 및 모바일 390×844에서 확인. 모바일 문서 가로 넘침 없음. 검사 중 브라우저 오류 로그 없음.

관계도 화면 JS 번들은 이전 약 493.74KB(gzip 156.96KB)에서 약 20KB(gzip 7.6KB)로 감소했다. 의존성을 앱에서 가져오지 않게 된 결과이며 전체 사이트 다운로드 크기가 그만큼 되었다는 뜻은 아니다.

## 남은 범위

전체 경제 데이터·Git 이력은 여전히 초기 공용 번들에 포함되어 약 2.86MB의 크기 경고가 남는다. 네트워크 첫 로딩까지 분리하려면 데이터 지연 로딩을 별도 검증해야 한다. 이번 변경은 관계도 상호작용과 반복 렌더링 비용에 집중했으며 모든 기기에서의 FPS 보장은 하지 않는다. 원문 경제 데이터는 변경하지 않았다.
